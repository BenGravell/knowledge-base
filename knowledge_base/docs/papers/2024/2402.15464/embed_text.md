## Introduction

Data association is broadly defined as the correspondence of identical/similar elements across sets of data, and is a key component of many robotics and computer vision applications, such as localization and mapping \[(https://arxiv.org/html/2402.15464v1#bib.bib3), (https://arxiv.org/html/2402.15464v1#bib.bib4), (https://arxiv.org/html/2402.15464v1#bib.bib5)\], point cloud registration \[(https://arxiv.org/html/2402.15464v1#bib.bib6), (https://arxiv.org/html/2402.15464v1#bib.bib7)\], shape alignment \[(https://arxiv.org/html/2402.15464v1#bib.bib8)\], object detection \[(https://arxiv.org/html/2402.15464v1#bib.bib9)\], data fusion \[(https://arxiv.org/html/2402.15464v1#bib.bib10), (https://arxiv.org/html/2402.15464v1#bib.bib11)\], and multi-object tracking \[(https://arxiv.org/html/2402.15464v1#bib.bib12)\]. In these applications, it is crucial that data association is solved correctly and fast.

In point cloud registration, for example, we seek to find the rigid transformation (rotation/translation) that aligns two sets of 3D points. This requires associating points in one set with their corresponding points in the other set. Local registration techniques such as the Iterative Closest Point (ICP) algorithm \[(https://arxiv.org/html/2402.15464v1#bib.bib13)\] associate points based on their nearest neighbor. These associations are generally wrong if the point clouds are not aligned well initially, leading to wrong registration. Better associations can be established by matching descriptors that are computed around each point in the point cloud and describe the local geometry and appearance of a point (e.g., classical FPFH \[(https://arxiv.org/html/2402.15464v1#bib.bib14)\] or modern learning-based 3DMatch \[(https://arxiv.org/html/2402.15464v1#bib.bib15)\]). However, due to noise, repetitive patterns, small overlap between the point clouds, etc., these putative associations can have extreme outlier ratios (e.g., FPFH associations in Section [V-C](https://arxiv.org/html/2402.15464v1#S5.SS3 "V-C Registration Benchmark—Real-World Point Clouds ‣ V Experimental Evaluations ‣ CLIPPER+: A Fast Maximal Clique Algorithm for Robust Global Registration") are $99\%$ outliers/wrong). In these high-outlier regimes, existing outlier rejection techniques (such as the general RANSAC framework \[(https://arxiv.org/html/2402.15464v1#bib.bib16)\] or specific frameworks for point cloud registration \[(https://arxiv.org/html/2402.15464v1#bib.bib17)\]) either return wrong results or have impractical runtime (e.g., RANSAC's runtime grows exponentially in outlier ratio \[(https://arxiv.org/html/2402.15464v1#bib.bib6)\]).

To address these issues, we present the CLIPPER+ algorithm. CLIPPER+ formulates the data association problem as a graph, in which the inlier/correct associations are the maximum clique. This formulation is robust to high outlier ratios and applicable to any problem that admits invariants (see Section [III](https://arxiv.org/html/2402.15464v1#S3 "III Graph-Theoretic Robust Registration ‣ CLIPPER+: A Fast Maximal Clique Algorithm for Robust Global Registration")) such as point, line, and plane could registration \[(https://arxiv.org/html/2402.15464v1#bib.bib1), (https://arxiv.org/html/2402.15464v1#bib.bib18), (https://arxiv.org/html/2402.15464v1#bib.bib19)\]. To address the high computational complexity of finding the maximum clique (NP-hardness), CLIPPER+ finds an approximate solution instead, which is obtained from combining an improved version of our prior work, CLIPPER \[(https://arxiv.org/html/2402.15464v1#bib.bib1)\], and the greedy maximal clique algorithm in \[(https://arxiv.org/html/2402.15464v1#bib.bib2)\]. CLIPPER+ runs in polynomial time and outperforms state-of-the-art algorithms in maximum clique estimation accuracy (Section [V-A](https://arxiv.org/html/2402.15464v1#S5.SS1 "V-A Maximum Clique Benchmark—DIMACS ‣ V Experimental Evaluations ‣ CLIPPER+: A Fast Maximal Clique Algorithm for Robust Global Registration")). Further, CLIPPER+ solutions are shown to be exact (i.e., the maximum clique) in over $99\%$ of the point cloud registration trials (Section [V-C](https://arxiv.org/html/2402.15464v1#S5.SS3 "V-C Registration Benchmark—Real-World Point Clouds ‣ V Experimental Evaluations ‣ CLIPPER+: A Fast Maximal Clique Algorithm for Robust Global Registration")).

## Related Work

Robust registration: In robotic applications of data association, such as registration, formulations that are robust to uncertainties (such as extreme noise and outliers) are based on globally optimal solvers, such as Branch and Bound \[(https://arxiv.org/html/2402.15464v1#bib.bib20), (https://arxiv.org/html/2402.15464v1#bib.bib21), (https://arxiv.org/html/2402.15464v1#bib.bib6)\], and combinatorial approaches for maximum consensus \[(https://arxiv.org/html/2402.15464v1#bib.bib22)\]. These methods can tolerate extreme outlier ratios, but have worst-case exponential complexity and are slow in practice. To address this issue, fast heuristics such as RANSAC \[(https://arxiv.org/html/2402.15464v1#bib.bib16)\] and its variants \[(https://arxiv.org/html/2402.15464v1#bib.bib23)\], graduated non-convexity \[(https://arxiv.org/html/2402.15464v1#bib.bib17), (https://arxiv.org/html/2402.15464v1#bib.bib24), (https://arxiv.org/html/2402.15464v1#bib.bib25)\], or iterative local solvers for M-estimation \[(https://arxiv.org/html/2402.15464v1#bib.bib26), (https://arxiv.org/html/2402.15464v1#bib.bib27)\] are used, however, they are prone to failures in high-outlier regimes \[(https://arxiv.org/html/2402.15464v1#bib.bib6), (https://arxiv.org/html/2402.15464v1#bib.bib7), (https://arxiv.org/html/2402.15464v1#bib.bib28)\].

Graph-theoretic formulation: The dichotomy between robustness and runtime can be resolved in some data association settings that admit "invariants" (see Section [III](https://arxiv.org/html/2402.15464v1#S3 "III Graph-Theoretic Robust Registration ‣ CLIPPER+: A Fast Maximal Clique Algorithm for Robust Global Registration"), and \[(https://arxiv.org/html/2402.15464v1#bib.bib19), (https://arxiv.org/html/2402.15464v1#bib.bib1), (https://arxiv.org/html/2402.15464v1#bib.bib18)\]) by formulation in a graph-theoretic framework. Recent algorithms that leverage this framework are CLIPPER \[(https://arxiv.org/html/2402.15464v1#bib.bib1)\], TEASER \[(https://arxiv.org/html/2402.15464v1#bib.bib7)\], and ROBIN \[(https://arxiv.org/html/2402.15464v1#bib.bib19)\] for global point cloud registration, robust to more than $99\%$ outliers and suitable for real-time applications, and PCM \[(https://arxiv.org/html/2402.15464v1#bib.bib4)\] for pairwise-consistent loop closures in SLAM. This graph-theoretic formulation can be traced back to Bailey et al. \[(https://arxiv.org/html/2402.15464v1#bib.bib29)\] for 2D LiDAR registration as a maximum common subgraph problem, for which the maximum clique indicated the correct data association. Leordeanu and Hebert \[(https://arxiv.org/html/2402.15464v1#bib.bib30)\] extended this graph-theoretic framework to weighted consistency graphs. Enqvist et al. \[(https://arxiv.org/html/2402.15464v1#bib.bib31)\] noted the suboptimality of \[(https://arxiv.org/html/2402.15464v1#bib.bib30)\] and proposed a vertex covering formulation, essentially an alternative to the maximum clique formulation of \[(https://arxiv.org/html/2402.15464v1#bib.bib29)\]. Parra et al. \[(https://arxiv.org/html/2402.15464v1#bib.bib32)\] proposed a practical maximum clique algorithm for geometric consistency based on branch and bound and graph coloring. Recently, Zhang et al. \[(https://arxiv.org/html/2402.15464v1#bib.bib33)\] have shown that the registration problem can be solved by relaxing the maximum clique constraint and using the maximal cliques instead.

Maximum clique estimation: Finding the maximum clique is a well-known NP-hard problem in its full generality \[(https://arxiv.org/html/2402.15464v1#bib.bib34)\], meaning that the complexity of finding the solution using exact algorithms (e.g., \[(https://arxiv.org/html/2402.15464v1#bib.bib2)\]) grows exponentially in graph size, which is impractical for data association applications. An approximate (maximal clique) solution can however be found by polynomial-time algorithms. Notable algorithms in this setting are Pelillo \[(https://arxiv.org/html/2402.15464v1#bib.bib35)\] and Ding et al. \[(https://arxiv.org/html/2402.15464v1#bib.bib36)\], based on the Motzkin-Straus formulation \[(https://arxiv.org/html/2402.15464v1#bib.bib37)\], Belachew and Gillis \[(https://arxiv.org/html/2402.15464v1#bib.bib38)\] based on symmetric rank-one nonnegative Matrix approximation, and our prior CLIPPER algorithm \[(https://arxiv.org/html/2402.15464v1#bib.bib1)\] based on a continuous relaxation.

## Graph-Theoretic Robust Registration

The key idea for creating robustness to extreme outlier ratios is to find the largest set of jointly consistent data and/or associations. This problem can be formulated as a graph, in which this set is represented by the maximum clique. In what follows, we introduce this graph-theoretic framework and its use case for point cloud registration.

Point cloud registration: The objective of point cloud registration is to find the rigid transformation that aligns a set of points to their corresponding points in another set. The main challenge is finding the correct correspondences as usually only a subset of the points match, and, the points do not align perfectly due to noise. An outlier can be a point in one set that does not have a counterpart in the other set, or an association that matches wrong points across the sets. Our focus here is associations, and henceforth outliers imply outlier associations. Fig. (https://arxiv.org/html/2402.15464v1#S1.F1 "Figure 1 ‣ I Introduction ‣ CLIPPER+: A Fast Maximal Clique Algorithm for Robust Global Registration") illustrates a point cloud registration example where we seek to find the blue bunny in the cluttered point cloud.

Maximum likelihood solution: In the absence of prior knowledge and when outliers are random, unbiased, and unstructured, the largest set of jointly consistent associations are inliers for the maximum likelihood solution. For point cloud registration, two associations are consistent if their endpoints are equidistant, and therefore can be aligned by a rigid transformation. In Fig (https://arxiv.org/html/2402.15464v1#S1.F1 "Figure 1 ‣ I Introduction ‣ CLIPPER+: A Fast Maximal Clique Algorithm for Robust Global Registration"), the green associations align $3$ points while the red associations align $2$ points. Thus, the green associations are the inliers and can be used to compute the correct maximum likelihood solution.

Graph formulation: Finding the largest set of jointly consistent associations can be formulated as a maximum clique problem. Given $n$ associations, the consistency graph is a graph of $n$ vertices where each vertex represents an association. An edge between two vertices indicates that the associations are consistent. In Fig. (https://arxiv.org/html/2402.15464v1#S1.F1 "Figure 1 ‣ I Introduction ‣ CLIPPER+: A Fast Maximal Clique Algorithm for Robust Global Registration"), an edge between two vertices of the consistency graph (shown on the right) indicates consistency of corresponding associations. For example, there is an edge between vertices/associations $2$ and $3$ as their endpoints are equidistant ($d = d^{\prime}$), while there is no edge between vertices/associations $1$ and $3$. Given two associations with endpoint distances $d$ and $d^{\prime}$, due to noise, often a consistency threshold $\epsilon$ is used where if ${|{d - d^{\prime}}|} < \epsilon$, the associations are deemed consistent.

A clique is a subset of vertices where every pair of vertices within that subset is connected by an edge. The maximum clique is the clique with the largest number of vertices. A maximal clique is a clique that is not contained in a larger clique. The maximum clique in Fig. (https://arxiv.org/html/2402.15464v1#S1.F1 "Figure 1 ‣ I Introduction ‣ CLIPPER+: A Fast Maximal Clique Algorithm for Robust Global Registration") consists of vertices $2$, $3$, and $5$. Vertices $1$ and $4$ form a maximal clique.

Invariants: The graph-theoretic framework can be applied to a broad array of data association problems in robotics. An invariant is a quantity that remains unchanged across the sets. The invariant used for the point cloud registration example above was the Euclidean distance between the endpoints. Invariants can be defined to register lines \[(https://arxiv.org/html/2402.15464v1#bib.bib1)\], planes \[(https://arxiv.org/html/2402.15464v1#bib.bib18)\], 2D-3D visual features \[(https://arxiv.org/html/2402.15464v1#bib.bib19)\], etc. Examples in this work, however, focus on point cloud registration.

### IV-A Degeneracy-Ordered Greedy Maximal Clique Algorithm

Algorithm (https://arxiv.org/html/2402.15464v1#alg1 "Algorithm 1 ‣ IV Maximal Clique Algorithms ‣ CLIPPER+: A Fast Maximal Clique Algorithm for Robust Global Registration") presents a greedy approach for finding a maximal clique. Starting from an empty clique (line 3), we grow the clique one vertex at a time by looping through the vertices (line 6). For each vertex $v$ that this loop examines, the algorithm adds $v$ to the current clique if it is connected to every vertex that is already in the clique, and discards $v$ otherwise (lines 13-16). This algorithm has the overall runtime of $O{({\delta{|E|}})}$, where $\delta$ is the maximum vertex degree and $|E|$ is the number of edges \[(https://arxiv.org/html/2402.15464v1#bib.bib2)\].

The maximal clique returned by the greedy approach depends on the initial vertex chosen to grow the clique, and the ordering of vertices (as they are sequentially examined to be added to the current clique or discarded). A descending ordering of vertices by their core number greatly improves the odds of finding a large maximal clique (and possibly the maximum clique), as leveraged in Algorithm (https://arxiv.org/html/2402.15464v1#alg1 "Algorithm 1 ‣ IV Maximal Clique Algorithms ‣ CLIPPER+: A Fast Maximal Clique Algorithm for Robust Global Registration") (lines 5 and 10). Mathematically, the core number or degeneracy of a vertex $v$ is the largest integer $k$ such that the degree of $v$ remains non-zero when all vertices of degree less than $k$ are recursively removed from the graph. The core number of vertices can be computed efficiently in $O{({|E|})}$ by Batagelj and Zaversnik's algorithm \[(https://arxiv.org/html/2402.15464v1#bib.bib39)\].

That is, the entries of a solution vector $u^{*} \in {\mathbb{R}}_{+}^{n}$ are either $0$ or equal to a positive scalar $c > 0$. These positive entries are indicators of vertices that form a maximal clique. Noting that ((https://arxiv.org/html/2402.15464v1#S4.E15 "15 ‣ IV-B Continuous-Relaxation Maximal Clique Algorithm ‣ IV Maximal Clique Algorithms ‣ CLIPPER+: A Fast Maximal Clique Algorithm for Robust Global Registration")) can be (locally) solved in polynomial time by using a gradient-based solver, and the one-to-one correspondence between the optima of ((https://arxiv.org/html/2402.15464v1#S4.E15 "15 ‣ IV-B Continuous-Relaxation Maximal Clique Algorithm ‣ IV Maximal Clique Algorithms ‣ CLIPPER+: A Fast Maximal Clique Algorithm for Robust Global Registration")) and the (NP-hard) maximum clique problem ((https://arxiv.org/html/2402.15464v1#S4.E7 "7 ‣ IV-B Continuous-Relaxation Maximal Clique Algorithm ‣ IV Maximal Clique Algorithms ‣ CLIPPER+: A Fast Maximal Clique Algorithm for Robust Global Registration")), one may think that the maximum clique problem can be solved in polynomial time. Note, however, that ((https://arxiv.org/html/2402.15464v1#S4.E15 "15 ‣ IV-B Continuous-Relaxation Maximal Clique Algorithm ‣ IV Maximal Clique Algorithms ‣ CLIPPER+: A Fast Maximal Clique Algorithm for Robust Global Registration")) is a nonlinear optimization problem, potentially with many local optima, and depending on the initial guess the solver can converge to a local optimum instead of the global optimum. Finding the global optimum of ((https://arxiv.org/html/2402.15464v1#S4.E15 "15 ‣ IV-B Continuous-Relaxation Maximal Clique Algorithm ‣ IV Maximal Clique Algorithms ‣ CLIPPER+: A Fast Maximal Clique Algorithm for Robust Global Registration")), hence, remains an NP-hard problem.

Optimization algorithm: We present a custom solver for ((https://arxiv.org/html/2402.15464v1#S4.E15 "15 ‣ IV-B Continuous-Relaxation Maximal Clique Algorithm ‣ IV Maximal Clique Algorithms ‣ CLIPPER+: A Fast Maximal Clique Algorithm for Robust Global Registration")) based on a projected gradient ascent approach, as described in Algorithm (https://arxiv.org/html/2402.15464v1#alg2 "Algorithm 2 ‣ IV-B Continuous-Relaxation Maximal Clique Algorithm ‣ IV Maximal Clique Algorithms ‣ CLIPPER+: A Fast Maximal Clique Algorithm for Robust Global Registration"). Our approach is similar to the algorithm in our previous work CLIPPER \[(https://arxiv.org/html/2402.15464v1#bib.bib1)\]; however, compared to \[(https://arxiv.org/html/2402.15464v1#bib.bib1)\], Algorithm (https://arxiv.org/html/2402.15464v1#alg2 "Algorithm 2 ‣ IV-B Continuous-Relaxation Maximal Clique Algorithm ‣ IV Maximal Clique Algorithms ‣ CLIPPER+: A Fast Maximal Clique Algorithm for Robust Global Registration") is significantly improved and uses the Armijo procedure for selecting the appropriate step size, which leads to more accurate results (as we will show in the comparisons).

Problem ((https://arxiv.org/html/2402.15464v1#S4.E15 "15 ‣ IV-B Continuous-Relaxation Maximal Clique Algorithm ‣ IV Maximal Clique Algorithms ‣ CLIPPER+: A Fast Maximal Clique Algorithm for Robust Global Registration")) is nonlinear with many local optima in general (corresponding to maximal cliques). To improve the odds of finding the global optimum (maximum clique) and escape local optima, in Algorithm (https://arxiv.org/html/2402.15464v1#alg2 "Algorithm 2 ‣ IV-B Continuous-Relaxation Maximal Clique Algorithm ‣ IV Maximal Clique Algorithms ‣ CLIPPER+: A Fast Maximal Clique Algorithm for Robust Global Registration") we use a homotopy approach where we increase $d$ incrementally in an outerloop (lines 7-26). As the penalty parameter $d$ increases incrementally by $\Delta d$ in each iteration of the outerloop (line 26), the elements of $u$ that violate the clique constraints are penalized further and $u$ converges to a feasible solution. This process continues until $d$ is large enough ($d \geq n$) and $u$ converges to a binary state, corresponding to a maximal clique. The $\Delta d$ increments can be chosen as a small constant (as done in \[(https://arxiv.org/html/2402.15464v1#bib.bib38)\]), however, in our implementation, we use a greedy scheme where we increase $d$ until the smallest element of $u$ that violates the clique constraint goes to zero in the next iteration. In the final step (line 27), the vertices of the maximal clique are identified as the non-zero elements of $u$.

The innerloop (lines 13-25) ensures that for each $d$ increment enough iterations of the gradient ascent are performed for the solution $u$ to reach a steady state. Noting that the constraint manifold of the optimization problem ((https://arxiv.org/html/2402.15464v1#S4.E15 "15 ‣ IV-B Continuous-Relaxation Maximal Clique Algorithm ‣ IV Maximal Clique Algorithms ‣ CLIPPER+: A Fast Maximal Clique Algorithm for Robust Global Registration")) is ${\mathbb{R}}_{+}^{n} \cap S^{n}$, where $S^{n}$ is the unit sphere, to speed up the convergence, we project the gradient ${{\nabla F}{(u)}}\overset{\text{def}}{=}{2M_{d}u}$ onto the tangent bundle of $S^{n}$ at $u$ and move along the orthogonal projection ${{\nabla F_{\perp}}{(u)}} = {2{({I - {uu^{\top}}})}M_{d}u}$ (line 11).

To find an appropriate step size $\alpha$ along the projected gradient, we use backtracking line search (lines 15-24) with the Armijo procedure (lines 21-24), which guarantees a sufficient increase in the objective at each innerloop iteration. The convergence of the algorithm to a first-order optimal point is guaranteed by the convergence property of the projected gradient with Armijo steps \[(https://arxiv.org/html/2402.15464v1#bib.bib41)\]. The solution update is computed in line 16, retracted back onto the constraint manifold (line 17), and the gradient ascent continues until convergence.

Computational Complexity: The worst-case complexity of Algorithm (https://arxiv.org/html/2402.15464v1#alg2 "Algorithm 2 ‣ IV-B Continuous-Relaxation Maximal Clique Algorithm ‣ IV Maximal Clique Algorithms ‣ CLIPPER+: A Fast Maximal Clique Algorithm for Robust Global Registration") is $O{(n^{4})}$. This is because the gradient computation (line 19) involves matrix-vector multiplications, which have $O{(n^{2})}$ complexity, and profiling shows this is where most of the time is spent. The number of backtracking iterations (line 15) and gradient ascent iterations (line 13) can vary depending on the parameters and the data matrix, but it is linear in problem size ($O{(n)}$) for quadratic objective ${F{(u)}} = {u^{\top}M_{d}u}$. Lastly, the number of outerloop iterations (line 7) depends on $\Delta d$ increments (line 26) required to reach $d \geq n$ (at which point the solution is guaranteed to converge to the binary state). This is also linear in problem size.

### IV-C CLIPPER+ Maximal Clique Algorithm

Both Algorithms (https://arxiv.org/html/2402.15464v1#alg1 "Algorithm 1 ‣ IV Maximal Clique Algorithms ‣ CLIPPER+: A Fast Maximal Clique Algorithm for Robust Global Registration") and (https://arxiv.org/html/2402.15464v1#alg2 "Algorithm 2 ‣ IV-B Continuous-Relaxation Maximal Clique Algorithm ‣ IV Maximal Clique Algorithms ‣ CLIPPER+: A Fast Maximal Clique Algorithm for Robust Global Registration") are algorithms for finding maximal cliques. The greedy approach of Algorithm (https://arxiv.org/html/2402.15464v1#alg1 "Algorithm 1 ‣ IV Maximal Clique Algorithms ‣ CLIPPER+: A Fast Maximal Clique Algorithm for Robust Global Registration") runs fast but gives relatively less accurate estimates of the maximum clique size when the graph is not sparse. In contrast, the optimization approach of Algorithm (https://arxiv.org/html/2402.15464v1#alg2 "Algorithm 2 ‣ IV-B Continuous-Relaxation Maximal Clique Algorithm ‣ IV Maximal Clique Algorithms ‣ CLIPPER+: A Fast Maximal Clique Algorithm for Robust Global Registration") is relatively slower but more accurate. The main motivation of the proposed CLIPPER+ algorithm is to combine these two algorithms and thereby combine their relative benefits.

The enable this combination, recall that the core number of a vertex is the largest integer $k$ such that the degree of the vertex remains non-zero when all vertices of degree less than $k$ are removed. If a graph contains a clique of size $k$, then each vertex in the clique must have a degree of $k - 1$ or larger, and therefore a core number of $k - 1$ or larger. For this reason, if we hope to find a larger clique, say of size $k + 1$, then only vertices that have a core number $k$ or higher can be candidates. Using this observation, CLIPPER+, detailed in Algorithm (https://arxiv.org/html/2402.15464v1#alg3 "Algorithm 3 ‣ IV-B Continuous-Relaxation Maximal Clique Algorithm ‣ IV Maximal Clique Algorithms ‣ CLIPPER+: A Fast Maximal Clique Algorithm for Robust Global Registration"), first runs the greedy algorithm and obtains a maximal clique (line 4). Assuming this clique has size $k$, if the graph contains a larger clique, then vertices must have core numbers of $k$ or larger. Therefore, the algorithm prunes the graph by removing vertices with core numbers strictly less than $k$ (line 6). The pruning effectively limits the search space for the optimization (line 10) by reducing the number of vertices, which improves the runtime.

If the clique recovered by the greedy algorithm is the maximum clique, then pruning the graph removes all the vertices and therefore we can terminate early (line 7). This early termination particularly occurs when the graph is sparse, which leads to a significant speed-up over running the optimization-based algorithm on the original graph.

When the optimization-based algorithm is required, the initial guess used for the optimization can be chosen strategically to improve the chance of finding the maximum clique. This can be done by choosing an initial guess vector that is a binary complement of the clique found from the greedy approach (line 9), and thus help the algorithm to converge to a different clique solution. Lastly, the best solution is selected as the largest clique (line 11).

Computational Complexity: The worst-cast complexity of Algorithm (https://arxiv.org/html/2402.15464v1#alg3 "Algorithm 3 ‣ IV-B Continuous-Relaxation Maximal Clique Algorithm ‣ IV Maximal Clique Algorithms ‣ CLIPPER+: A Fast Maximal Clique Algorithm for Robust Global Registration") is $O{(n^{4})}$. This is because it sequentially combines Algorithms (https://arxiv.org/html/2402.15464v1#alg1 "Algorithm 1 ‣ IV Maximal Clique Algorithms ‣ CLIPPER+: A Fast Maximal Clique Algorithm for Robust Global Registration") and (https://arxiv.org/html/2402.15464v1#alg2 "Algorithm 2 ‣ IV-B Continuous-Relaxation Maximal Clique Algorithm ‣ IV Maximal Clique Algorithms ‣ CLIPPER+: A Fast Maximal Clique Algorithm for Robust Global Registration"), and thus inherits the highest worst-case complexity of its components (all other steps in Algorithm (https://arxiv.org/html/2402.15464v1#alg3 "Algorithm 3 ‣ IV-B Continuous-Relaxation Maximal Clique Algorithm ‣ IV Maximal Clique Algorithms ‣ CLIPPER+: A Fast Maximal Clique Algorithm for Robust Global Registration") have lower complexity). This basic worst-case complexity analysis is independent of any input graph structure. The numerical results in the experimental section provide a good indication of how the complexity translates to runtimes for various graph sizes in the practical applications.

### V-C Registration Benchmark---Real-World Point Clouds

Datasets: We use sequences in the real-world 7-Scenes \[(https://arxiv.org/html/2402.15464v1#bib.bib42)\], Sun3D \[(https://arxiv.org/html/2402.15464v1#bib.bib45)\], and ETH \[(https://arxiv.org/html/2402.15464v1#bib.bib46)\] datasets (similar to 3DMatch \[(https://arxiv.org/html/2402.15464v1#bib.bib15)\] and 3DSmoothNet \[(https://arxiv.org/html/2402.15464v1#bib.bib47)\] evaluations). Sun3D and 7-Scenes are dense indoor RGB-D point clouds, while ETH is an outdoor LiDAR point cloud. In each sequence, we consider pairs of point clouds (or scans) that have an overlap. To increase registration speed, we downsample the point clouds by discretizing the 3D space into cubes of size $\epsilon = {0.05m}$ for 7-Scenes and Sun3D datasets, and $\epsilon = {0.1m}$ for the ETH dataset, and using the mean of the point coordinates in each cube as a single-point representative. For each downsampled point, FPFH descriptor vectors \[(https://arxiv.org/html/2402.15464v1#bib.bib14)\] are computed and associated bilaterally based on their $l_{2}$ norm distance using the k-nearest neighbors algorithm. To generate the ground truth for our evaluations, we use the exact maximum clique algorithm of \[(https://arxiv.org/html/2402.15464v1#bib.bib2)\] to find the largest set of geometrically consistent associations in these putative FPFH associations. We store results if this maximum clique solution correctly registers the point clouds according to the ground truth provided by the datasets---the maximum clique/likelihood solution may register points wrongly due to practical limitations such as repetitive patterns (perceptual aliasing), insignificant overlap between the point clouds, and lack of any inlier associations caused by downsampling and FPFH inaccuracies. For evaluations, the consistency graph is generated according to Section [III](https://arxiv.org/html/2402.15464v1#S3 "III Graph-Theoretic Robust Registration ‣ CLIPPER+: A Fast Maximal Clique Algorithm for Robust Global Registration") from putative FPFH associations, using the downsampling $\epsilon$ as the consistency threshold. An evaluation instance is shown in Fig. (https://arxiv.org/html/2402.15464v1#S5.F6 "Figure 6 ‣ V-B Registration Benchmark—Stanford Bunny ‣ V Experimental Evaluations ‣ CLIPPER+: A Fast Maximal Clique Algorithm for Robust Global Registration").

Evaluation: Table [II](https://arxiv.org/html/2402.15464v1#S5.T2 "TABLE II ‣ V-B Registration Benchmark—Stanford Bunny ‣ V Experimental Evaluations ‣ CLIPPER+: A Fast Maximal Clique Algorithm for Robust Global Registration") presents the evaluation results for all datasets and algorithms. CLIPPER+ outperforms all algorithms in accuracy on all datasets/sequences. The greedy algorithm has the smallest runtime at the expense of the lowest overall accuracy. The standalone optimization algorithm has similar accuracy to CLIPPER+. However, except on the last sequence, it is around $2$x slower. This demonstrates the advantage of CLIPPER+ over its standalone greedy and optimization components.

Lastly, we point out the high outlier ratios of FPFH associations (e.g., on average, $99.4\%$ of associations in the `wood_autumn` sequence are outliers). Due to the maximum clique solution correctly registering the point clouds in our benchmark, the accuracy ratio $r$ shows the point cloud registration success rate. Thus, CLIPPER+ correctly registers the point clouds in $99\%$ of the trials despite extreme outlier percentages. This is what distinguishes CLIPPER+ from existing robust registration frameworks (such as RANSAC \[(https://arxiv.org/html/2402.15464v1#bib.bib16)\]), that can fail in these high-outlier regimes.

## Conclusion and Future Directions

We presented CLIPPER+, a maximal-clique-finding algorithm for unweighted graphs that enables robust global registration in robotics and computer vision applications. Future work includes investigating alternative optimization methods such as second-order or quasi-Newton methods, and an extension to the weighted graphs based on our previous work \[(https://arxiv.org/html/2402.15464v1#bib.bib1)\] (designed for weighted graphs) and an extension of core numbers to weighted settings (studied in \[(https://arxiv.org/html/2402.15464v1#bib.bib48)\]). We also plan to integrate the algorithm in point cloud registration pipelines \[(https://arxiv.org/html/2402.15464v1#bib.bib7)\] as the outlier rejection module to improve the runtime and outlier rejection capacity.
